# jt-filework

> 鍵盤優先、滑鼠完備的檔案工作區，支援 macOS、Windows 與 Linux。

**[網站](https://jasoncheng7115.github.io/jt-filework/?lang=zh-tw)** ·
**[完整功能規格](https://jasoncheng7115.github.io/jt-filework/features.html?lang=zh-tw)** ·
[English](README.md)

全鍵模式下，常用的檔案操作各自對應一個按鍵——複製、移動、更名、檢視、標記
——不必按住組合鍵，也不必到選單裡翻。這套鍵盤放在一個現代原生檔案管理器之
上：可遞迴分割的面板、每個面板各自獨立的分頁、真正的預覽、可以瀏覽的壓縮
檔、透過 SFTP 的遠端資料夾，以及一份會告訴你哪**一類**檔案填滿磁碟的用量
報告。

作者：Jason Cheng（Jason Tools）。

**狀態：0.6.0。** 已在 macOS（Apple Silicon）與 Windows（x64）建置並執行，
Linux 可從原始碼建置。545 個測試通過。

## 目前做得到的事

以下每一項都已經完成並可用，不是規劃。

### 鍵盤

兩套設定檔，都是**資料檔而非程式碼**（`keymaps/`）：

- **全鍵模式** — 一個字母、一個命令。`C` 複製、`M` 移動、`D` 移到回收筒、
  `V` 檢視、`Z` 計算資料夾大小、`P` 或 `\` 輸入路徑、`Space` 標記。當下可以按
  的鍵就寫在視窗下緣，而且會跟著游標所在的東西改變。
- **原生模式** — 作業系統自己的操作鍵，給肌肉記憶說「Cmd-C」的時候。

一個綁定就是文字檔裡的一行。新增一個綁定，除了那個檔案之外什麼都不必重建。

### 面板、分頁與版面

- 遞迴分割樹——不是固定的兩個面板。任何面板都能水平或垂直再分，要多深都行。
- 每個面板擁有自己的分頁。分頁可以拉出來變成獨立視窗，或拖進另一個面板。
- 樹狀圖跟隨目前有鍵盤焦點的面板，包含跟到伺服器上。

### 選取就是標記

選取一列就是標記它，標記一列就是選取它。這兩件事原本是分開的概念，現在合而
為一——因為分開的結果是：用 Shift 選了六個檔案，卻一個都沒被勾起來。

### 檔案操作

複製、移動、重新命名、製作副本、移到回收筒、刪除、新增資料夾、新增檔案、批次
重新命名。每個操作都先規劃再執行，有進度、可取消、遇到衝突會回報而不是自己
猜。有復原。

### 壓縮檔與映像檔

| 格式 | 瀏覽 | 解壓 | 建立 |
| --- | --- | --- | --- |
| ZIP | ✅ | ✅ | ✅ |
| `.tar`、`.tar.gz` / `.tgz` | ✅ | ✅ | ✅ |
| `.tar.bz2`、`.tar.xz` | ✅ | ✅ | — |
| 單獨的 `.gz` / `.bz2` / `.xz` | ✅ | ✅ | — |
| ISO 9660（含 Joliet、Rock Ridge） | ✅ | ✅ | — 唯讀 |

在任何一種上按 Enter 都會開啟列表視窗：`Space` 標記、`C` 解出已標記的、
`X` 全部解出。

**每個讀取器都把輸入當成有敵意的。** 名稱會落在你所選資料夾之外的成員一律
**拒絕並回報**——絕不寫入、絕不悄悄改名——不論它怎麼拼：`../`、絕對路徑、
Windows 磁碟機代號、UNC 路徑開頭、任何平台上的反斜線。符號連結成員是拒絕而不是
建立。展開量的上限是對照**實際讀到的位元組**，不是對照標頭宣稱的數字，因為
會說謊的標頭正是解壓縮炸彈的本體。

ISO 讀取器是我們自己寫的而不是採用套件（ADR-0005），壓縮器選純 Rust 而不是
C 綁定（ADR-0006）。這兩個決定講的是同一件事:**剖析下載來的檔案時出錯，
應該是當掉，不是被入侵。**

`.7z` 與 `.rar` **不支援**，而且不會被標示成本版本打得開的壓縮檔。

### 遠端資料夾

SFTP，會檢查並記住主機金鑰，從 agent 或 `~/.ssh` 取用金鑰，兩者都不行時才
詢問密碼。密碼只保留在記憶體中直到行程結束，斷線即丟棄，永不寫入磁碟
（ADR-0004）。

瀏覽已完成。上傳、下載、在伺服器上重新命名與刪除屬於第二階段，尚未實作。

### 檢視

- **預覽面板**與**檢視視窗**：文字（含編碼與換行偵測）、十六進位、圖片、
  壓縮檔列表。
- 大檔案有刻意設下的上限:預覽索引前 4 MiB、檢視視窗 64 MiB，兩者都會標示
  「只顯示了檔案的一部分」。行索引是每行八個位元組，而且建立索引要讀過整個
  檔案——沒有上限的話，開一個好幾 GB 的日誌會讓視窗凍住，而且在顯示第一行
  之前就吃掉幾百 MB。
- **快速查看**在 macOS 上是真正的 `QLPreviewPanel`，與 Finder 開的是同一個。
  Windows 與 Linux 沒有對等的系統機制，所以那裡是**隱藏這個指令**，而不是
  提供一個按了沒反應的東西。

### 尋找

- **篩選**邊打邊縮小目前資料夾，命中的部分會標出來。
- **搜尋**會走訪子資料夾，結果邊找邊出現。
- **比較資料夾**把兩個面板並排，列出差異：只在這邊、只在那邊、不同、相同。
  子資料夾可選。依大小與修改時間比對——這條規則印在表格下方，而不是讓人
  自己假設。
- **磁碟用量**用一次走訪回答兩個問題：哪個子資料夾佔最多，以及**哪一類檔案**
  加起來最多。後者是多數工具回答不了的那一半。複製、移動、移到回收筒都可以直
  接在報告裡做，操作完成後那一層會重新統計。

### 其他

- 淺色、深色、跟隨系統三種主題。畫面上每個顏色都來自 Rust 裡解析的語意
  token；C++ 裡沒有任何一個字面顏色值。
- English 與台灣繁體中文，每一個使用者看得到的字串都在語系檔裡。少一個 key
  會讓測試失敗，而不是變成沒人注意到的標籤。
- 書籤、最近位置、磁碟區、伺服器——都在樹狀圖旁邊的側邊欄。

## 建置

Rust 工具鏈由 `rust-toolchain.toml` 釘在 1.98.0，`rustup` 會自動取得。建置
輸出放在原始碼樹之外（`~/.cache/jt-filework-target`、
`~/.cache/jt-filework-qt`），所以放在同步資料夾裡的 checkout 不會每次建置都
重新上傳好幾 GB。

### macOS

```bash
brew install qt cmake
./src/ui/qt6/build.sh release
```

release 建置同時會安裝到 `/Applications/jt-filework.app`。

### Linux

```bash
sudo apt install build-essential cmake ninja-build pkg-config \
     qt6-base-dev libqt6svg6-dev libgl1-mesa-dev
./src/ui/qt6/build.sh release
```

Ubuntu 22.04 內建 Qt 6.2、24.04 內建 6.4，兩者都能建置。但**執行中**跟隨
桌面的深淺色設定需要 Qt 6.5 以上；較舊的 Qt 只在啟動時判斷一次。

**請在你打算支援的最舊發行版上建置**:glibc 的相容性是單向的，22.04 編出來
的可以在 24.04 上跑，反過來不行。

### Windows

需要 MSVC Build Tools、CMake、Qt 6，以及 **NASM**（`aws-lc-sys` 經由 SFTP
的相依進來，它在 Windows 上要自己組譯）。完整步驟見
`docs/DEVELOPMENT_ENVIRONMENT.md`——那份文件存在的原因，是那台機器已經從備份
還原過一次。

### 測試

```bash
cargo test --workspace
cargo clippy --workspace --all-targets
```

測試套件包含架構測試:核心邏輯若相依 GUI 工具組、平台 `#cfg` 若出現在平台層
之外、鍵盤綁定若沒有對應的處理者、使用者可見字串若在任一語言中缺漏，建置就
會失敗。
