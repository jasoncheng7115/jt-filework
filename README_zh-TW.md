# jt-filework

> 鍵盤優先、滑鼠完備的檔案工作區，支援 macOS、Windows 與 Linux。

**[網站](https://jasoncheng7115.github.io/jt-filework/?lang=zh-tw)** ·
**[完整功能規格](https://jasoncheng7115.github.io/jt-filework/features.html?lang=zh-tw)** ·
[English](README.md)

全鍵模式下，常用的檔案操作一個按鍵就做完：複製、移動、更名、檢視、標記。
不用組合鍵，也不用翻選單。底下是一個原生的檔案管理器：面板可以一直切下去，
每個面板有自己的分頁，預覽是真的預覽，壓縮檔可以直接瀏覽，遠端資料夾走
SFTP，磁碟用量會告訴你是哪**一類**檔案把空間吃掉的。

作者：Jason Cheng（Jason Tools）。

**狀態：0.6.2。** macOS（Apple Silicon）跟 Windows（x64）已經在跑，Linux
自己建置。636 個測試通過。

## 目前做得到的事

下面這些都做完了、可以用，不是計畫。

### 鍵盤

兩套設定檔，都是**資料檔而非程式碼**（`keymaps/`）：

- **全鍵模式** — 一個字母、一個命令。`C` 複製、`M` 移動、`D` 移到回收筒、
  `V` 檢視、`Z` 計算資料夾大小、`P` 或 `\` 輸入路徑、`Space` 標記。現在可以按什麼
  就寫在視窗下緣，會跟著游標所在的東西換。
- **原生模式** — 作業系統自己的操作鍵，給習慣按「Cmd-C」的人。

一個綁定就是文字檔裡的一行。加一個綁定，除了那個檔案以外什麼都不用重建。

### 面板、分頁與版面

- 不是固定兩個面板。任何一個面板都能再往左右或上下切，要幾層就幾層。
- 每個面板有自己的分頁。分頁可以拉出來變成獨立視窗，也可以拖進另一個面板。
- 樹狀圖跟著現在有鍵盤焦點的面板走，跟到伺服器上也一樣。

### 選取就是標記

選一列就是標記它，標記一列就是選它。本來是分開的兩件事，現在合成一件。
分開的結果是：用 Shift 選了六個檔案，一個都沒被勾到。

### 檔案操作

複製、移動、更名、製作副本、移到回收筒、刪除、新增資料夾、新增檔案、批次更名。
每個操作都先算好再做，有進度、可以取消，遇到衝突會問，不會自己決定。可以復原。

### 壓縮檔與映像檔

| 格式 | 瀏覽 | 解壓 | 建立 |
| --- | --- | --- | --- |
| ZIP | ✅ | ✅ | ✅ |
| `.tar`、`.tar.gz` / `.tgz` | ✅ | ✅ | ✅ |
| `.tar.bz2`、`.tar.xz` | ✅ | ✅ | — |
| 單獨的 `.gz` / `.bz2` / `.xz` | ✅ | ✅ | — |
| ISO 9660（含 Joliet、Rock Ridge） | ✅ | ✅ | — 唯讀 |

按 Enter 就會開列表視窗：`Space` 標記、`C` 解出標記的、`X` 全部解出。

**每個讀取器都把輸入當成有問題的來看。** 檔名跑到你選的資料夾外面，一律
**擋下來並回報**，不寫、也不會自己改名。不管它怎麼寫都一樣：`../`、絕對路徑、
Windows 磁碟機代號、UNC 開頭、任何平台的反斜線。符號連結成員是擋下來，不建立。
解出來的量是照**實際讀到的位元組**去算，不是照標頭寫的數字，因為標頭會騙人，
這就是解壓縮炸彈在做的事。

ISO 讀取器是自己寫的，沒有用套件（ADR-0005）；壓縮器選純 Rust，不用 C 綁定
（ADR-0006）。兩個決定講的是同一件事：**剖析下載來的檔案出錯，應該是當掉，
不是被入侵。**

`.7z` 跟 `.rar` **不支援**，也不會被列成這一版打得開的壓縮檔。

### 把映像檔寫進 USB 隨身碟

只列可移除、外接、而且沒有裝著現在在跑的系統的磁碟；資料讀不齊的那顆根本不會
出現。順序是卸下、寫入、等磁碟寫完、讀回來、比對，而且比對預設就開著——快壞掉
的隨身碟跟假的隨身碟都是照單全收、讀出來是別的東西。權限只為了這一次操作跟系統
借：macOS 用 `authopen`，我們的程式碼完全不會用 root 跑，Linux 用 `pkexec`。

### 遠端資料夾

走 SFTP，主機金鑰會檢查也會記住。金鑰先找 agent，再找 `~/.ssh`，都不行才問
密碼。密碼只放在記憶體裡，程式關掉或斷線就丟，不會寫進磁碟（ADR-0004）。

瀏覽做好了。上傳、下載、在伺服器上更名跟刪除留到第二階段，還沒做。

### 檢視

- **預覽面板**與**檢視視窗**：文字（含編碼與換行偵測）、十六進位、圖片、
  壓縮檔列表。
- 大檔案有刻意設的上限：預覽索引前 4 MiB、檢視視窗 64 MiB，兩個都會標示
  「只顯示了檔案的一部分」。行索引每行要八個位元組，而且建索引得把整個檔案
  讀過一遍。沒有上限的話，開一個好幾 GB 的日誌會讓視窗卡死，第一行還沒畫
  出來就先吃掉幾百 MB。
- **快速查看**在 macOS 上是真的 `QLPreviewPanel`，跟 Finder 開的是同一個。
  Windows 跟 Linux 沒有對應的系統機制，所以那兩邊直接**把這個指令隱藏**，
  不做按了沒反應的東西。

### 尋找

- **篩選**邊打邊縮小目前資料夾，命中的部分會標出來。
- **搜尋**會走子資料夾，結果邊找邊出現。
- **比較資料夾**把兩個面板並排列出差異：只在這邊、只在那邊、不一樣、一樣。
  要不要含子資料夾自己決定。比對用大小跟修改時間，這條規則就印在表格下面，
  不用猜。
- **磁碟用量**掃一次回答兩個問題：哪個子資料夾最大，還有**哪一類檔案**加起來
  最大。第二個答案大部分工具都給不出來。複製、移動、丟回收筒都可以直接在報告
  裡做，做完那一層會重新統計。

### 其他

- 淺色、深色、跟隨系統三種主題。畫面上每個顏色都是 Rust 那邊解析出來的語意
  token，C++ 裡不會出現寫死的顏色值。
- English 跟台灣繁體中文，使用者看得到的字串全部在語系檔裡。少一個 key 就是
  測試失敗，不會變成沒人發現的標籤。
- 書籤、最近位置、磁碟區、伺服器，都在樹狀圖旁邊的側邊欄。

## 建置

Rust 工具鏈用 `rust-toolchain.toml` 釘在 1.98.0，`rustup` 會自己抓。建置輸出
丟在原始碼樹外面（`~/.cache/jt-filework-target`、`~/.cache/jt-filework-qt`），
所以放在同步資料夾裡的 checkout 不會每次建置都重傳好幾 GB。

### macOS

```bash
brew install qt cmake
./src/ui/qt6/build.sh release
```

release 建置同時會安裝到 `/Applications/jt-filework.app`。

### Linux

```bash
sudo apt install build-essential cmake ninja-build pkg-config \
     qt6-base-dev libqt6svg6-dev libgl1-mesa-dev
./src/ui/qt6/build.sh release
```

Ubuntu 22.04 內建 Qt 6.2、24.04 內建 6.4，兩個都能建置。但**執行中**跟著桌面
切深淺色要 Qt 6.5 以上，舊版的 Qt 只在啟動時看一次。

**要支援到哪個最舊的發行版，就在那台上面建置。** glibc 只往上相容：22.04
編出來的可以在 24.04 上跑，反過來不行。

### Windows

需要 MSVC Build Tools、CMake、Qt 6，還要 **NASM**（`aws-lc-sys` 是跟著 SFTP
進來的相依，它在 Windows 上要自己組譯）。完整步驟看
`docs/DEVELOPMENT_ENVIRONMENT.md`。那份文件會存在，是因為那台機器已經從備份
還原過一次。

### 測試

```bash
cargo test --workspace
cargo clippy --workspace --all-targets
```

測試套件裡有架構測試：核心邏輯相依到 GUI 工具組、平台 `#cfg` 跑到平台層外面、
鍵盤綁定沒有對應的處理者、使用者看得到的字串少了一邊，建置就會失敗。

先講清楚，不要讓人自己踩到才知道：

- SFTP 的寫入（上傳、下載、在伺服器上更名跟刪除）。
